OVERVIEW
--------
We ran 4–8 independent scraping sessions per benchmark per provider, each with
both an API condition (direct model call) and an Interface condition (model
accessed through its web UI). The gap of interest is Interface − API accuracy.

All data is scored with simple answer extraction (last numeric token for GSM8K,
letter extraction for MCQ benchmarks), except HellaSwag Claude Haiku interface
runs which use a GPT-4o-mini context-aware judge.

GSM8K is capped to 4 runs per provider in the final coverage analysis
(openllm_leaderboard.py), matching the system-prompt ablation run count and
avoiding the one miscounted Claude run (item 5 below).

HellaSwag accuracy is computed as correct/answered (answered = items where a
letter was successfully extracted), not correct/total. This avoids penalizing
extraction failures as wrong answers. This applies to all providers and
conditions uniformly.

All HellaSwag and ChatGPT interface runs use wrap_mcq_prompt=true, which prepends
"Answer the following multiple-choice question with a single letter (A, B, C, or D):"
to the query. Runs without this flag were excluded from HellaSwag analysis (see
DATA QUALITY section below).


DATA QUALITY ISSUES FIXED THIS SESSION
---------------------------------------

1. GSM8K Claude interface — incorrect "correct" column (2026-05-24)

   Runs 2026-03-13_23-21-09 (sessions 01/02) and
        2026-03-14_06-56-45_plus_11-55-31 (all sessions) and
        2026-03-14_19-23-28 (all sessions)
   had the "correct" column set to False for every row, even when the extracted
   answer matched the gold answer exactly. Root cause: a scoring bug during
   original CSV generation. Fix: recomputed correct = (answer == gold_answer).
   Runs 2026-03-13_11-59-25 and 2026-03-14_19-23-28 had no interface CSVs at
   all (JSON files existed in haiku/opus/sonnet-prefixed subdirs); new CSVs were
   created by extracting answers from the JSON responses.
   Apparent before-fix mean: Haiku 65.7%, Sonnet 48.8%, Opus 48.9%.
   True mean after fix:       Haiku 98.0%, Sonnet 97.8%, Opus 98.0%.

2. HellaSwag Claude Haiku — invalid runs without wrap_mcq (2026-05-24)

   11 runs from March 2026 and May 14 2026 lacked wrap_mcq_prompt. Without it,
   Claude Haiku treated the multi-paragraph HellaSwag prompts as documents to
   summarize, producing clarifying menus before the actual answer. Even with the
   context-aware judge, accuracy was ~40%. These 11 runs were excluded from the
   coverage CSV. 6 replacement runs (May 24 2026) with wrap_mcq were added.
   Excluded timestamps: 2026-03-10_22-46-39, 2026-03-11_17-44-27,
     2026-03-11_23-25-26, 2026-03-13_03-55-20, 2026-03-18_11-27-56,
     2026-05-14_01-20-44, 2026-05-14_10-57-37, 2026-05-14_12-26-15,
     2026-05-14_13-32-50, 2026-05-14_14-42-08.

3. HellaSwag ChatGPT — invalid runs without wrap_mcq (2026-05-24)

   5 May-14 Interface: Instant runs (64–76% accuracy) and 5 May-14
   Interface: Thinking runs (70–87% accuracy) were excluded. Their API
   counterparts were also excluded for consistency. Replaced by 5 May-24
   runs each with wrap_mcq.
   Excluded timestamps (Interface + API pairs):
     Instant:  2026-05-14_01-27-43, 2026-05-14_10-54-30,

4. ChatGPT Instant API extraction rate (note, not fixed)

   API runs for gpt-5.3-chat-latest on HellaSwag only yield 80–83 clean letter
   answers out of 93 questions (vs 88–93/93 for interface). The API model
   sometimes gives non-MCQ responses even with the question present in the
   prompt. Because HellaSwag now uses correct/answered as the denominator for
   all conditions, this is a coverage difference, not an accuracy difference per
   se — the apparent Interface > API gap for Instant HellaSwag is smaller than
   it would be under a correct/total formulation.

5. GSM8K capped to 4 runs (2026-05-24)

   openllm_leaderboard.py now limits GSM8K to the first 4 timestamps per
   provider. Claude had 6 raw timestamps (one of which had a scoring bug fixed
   in item 1 above, and the 5th/6th were later fill-in runs); ChatGPT and Gemini
   had 5. Using 4 aligns with the system-prompt ablation count and gives a clean
   apples-to-apples comparison across providers.
   Dropped for Claude:  2026-03-14_06-56-45_plus_11-55-31-gsm8k (run 5)
                        2026-03-14_19-23-28 (run 6)
   Dropped for ChatGPT: 2026-03-10_00-49-28 (run 5)
   Dropped for Gemini:  2026-03-16_23-47-51-gemini-gsm8k (run 5)

6. HellaSwag scoring: correct/answered denominator (2026-05-24)

   openllm_leaderboard.py now computes HellaSwag accuracy as
   correct / answered (items where a letter was extracted) instead of
   correct / total. Previously this was applied ad-hoc only to the ChatGPT
   Instant API condition; it is now uniform across all providers and conditions.
   Impact: small upward shift for conditions with extraction rate < 100%
   (primarily ChatGPT Instant API: ~88% extraction rate). The gap table below
   reflects the updated values (recomputed after this change).
